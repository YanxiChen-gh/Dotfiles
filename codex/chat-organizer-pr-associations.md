# Requested work, PRs and closure

Establish a PR's role in the conversation's requested outcome before using its state to choose a section. A PR belongs to tracked work when it delivers that request or the user explicitly asks the conversation to track, review or babysit it. The conversation need not have created the PR.

A citation, prior-art example or upstream dependency alone does not establish tracked work. Keep actual work PRs in `pullRequests`; retain useful contextual references separately with their role and the evidence for that role. Reassess inherited associations against the actual conversation instead of carrying them forward as facts.

Draft, review, merge and deployment gates govern the chat when those PRs belong to its requested outcome. A dependency can block requested implementation, but a completed scoping or research answer does not acquire implementation work because its proposal mentions an unfinished dependency. An assistant's suggested next step is not an additional user request.

Judge the latest requested scope, current execution and concrete outstanding action together. Preserve manual placements and pins. Do not infer ownership from a URL, title, author or PR status alone.

## Work-item closure

A finished agent response or delivered answer does not by itself close the work item. In an ongoing exploratory, planning or review conversation, a delivered scope, proposal or recommendation can still await Yanxi's review and next decision. Lack of an implementation request does not establish closure.

Use Done when contextual evidence establishes that the requested work item is finished and closed. User acceptance or closure is strong evidence; completed work and a verified end-state can also establish it without a mandatory closing phrase or manual action for every chat. When a concrete delivered proposal awaits review or decision and closure is uncertain, keep it open in Needs you or an appropriate review section. Idle or unread status alone does not establish a review obligation.

Persist direct user directions about an item's open/closed state with their provenance, and weigh them above inferred completion until fresher context establishes otherwise. Record the actual pending review or decision rather than inventing implementation work.
